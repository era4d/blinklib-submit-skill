# Install the Blink backlink Skill

Download the Skill package from the Blink website, then import that package with the target agent's normal Skill installation flow. The package is shared by Codex, Claude Code, and WorkBuddy; users should not manually copy individual files into hidden Skill directories.

Blink must export one complete `backlink-submit` package. Keep `SKILL.md`, `scripts/`, `references/`, and the generated `connection.json` together. Do not repackage only `SKILL.md`, add an extra nested wrapper directory, or edit internal paths after download.

## Requirements

- Node.js 18+ for the packaged Blink client.
- The default browser order is **Tabbit → built-in browser**. Use Tabbit with the installed `tabbit` skill and stable CLI; if unavailable, use a compatible built-in browser directly. Remote Chrome is not an automatic fallback.
- Python 3.10+ and Node.js with npm/npx compatible with the pinned Chrome DevTools MCP are required only for the optional bundled Chrome runner; no pip dependencies.
- A reachable Blink application API.
- A browser-control skill or tool that can inspect and fill forms.
- A browser surface that can close task tabs and preserve one unfinished tab with material progress when needed.

The Skill never reads browser passwords or cookies. Manual login, CAPTCHA, 2FA, Passkeys, and password managers remain under user control. When the user explicitly chooses an existing AdsPower desktop profile, the bundled Local API adapter may start that exact profile in visible mode; it does not modify the profile or operate CAPTCHA-solving extensions.

## Blink-provisioned connection

The downloaded package normally includes an installation-specific `connection.json` generated by Blink. It supplies the Blink API base URL and a scoped credential, so the installed agent can immediately read only the authorized queue.

Environment variables remain optional administrative overrides:

```text
BLINK_APP_URL=http://localhost:3000
BLINK_API_KEY=<install-specific key>
```

Treat the download as a credential-bearing installer artifact. Do not publish it, commit it to source control, forward it to another user, or reuse it for a different Blink account. Never print, paste, summarize, attach, or recursively dump `connection.json`; pass its path to the bundled scripts and let them read it internally. Every download receives an independent credential and does not revoke earlier installed packages. Revoke an obsolete or exposed installation explicitly from Blink's API-key page.

## Codex

Choose the downloaded Blink Skill package in Codex's Skill install/import flow. Install the complete package as one Skill. After discovery, invoke it as `$backlink-submit` or let Codex select it from its description.

`agents/openai.yaml` supplies Codex UI metadata and is ignored by other agents.

## Claude Code

Import or install the downloaded Blink package with the Claude Code Skill installation mechanism in use. Preserve the complete package and its relative layout. Invoke it as `/backlink-submit` or allow Claude to select it from its description.

The bundled Python runner handles Chrome connection, page opening and image upload when subprocess execution is supported. The agent interprets arbitrary forms and can use the runner's `browser-call` bridge to fill them through that same connection. If the environment restricts browser control to an exclusive adapter, use that adapter's documented workflow.

## WorkBuddy

Import or install the downloaded Blink package with WorkBuddy's Skill installation mechanism. Preserve the complete package and its relative layout. Prefer the installed `tabbit` skill and stable CLI, then a compatible built-in browser, following `references/platform-adapters.md` and the selected adapter's dependency preflight. A separate `web-access` or Remote Chrome adapter is used only when explicitly requested or resuming existing work.

WorkBuddy `web-access` may create background CDP tabs. Automatic mode can use those tabs. Untouched failed-login tabs are closed; every materially progressed unfinished form is preserved and foregrounded at batch end when supported.

Do not pair this Skill with CAPTCHA-solving, browser-barrier bypass, proxy rotation, fingerprint-evasion, or stealth-login helpers. AdsPower support is limited to an explicitly selected visible profile and loopback CDP connection as documented in `references/adspower.md`.

## Automatic execution

New and edited queues use automatic execution only. Saving the configuration authorizes the ordinary free form, supplied public product/contact facts, authorized assets, standard submission terms, and one final submission. Real login/verification/runtime blockers are preserved while other tasks continue, then reported together. Historic assisted queues keep their original authorization until their owner saves the automatic configuration.

Start or reconnect with `node scripts/blink-sequential-runner.mjs start`. Read `status`, execute its pending browser request, write a UTF-8 JSON receipt file, and run `respond --receipt-file PATH`. Repeat until the controller reports batch completion or a batch handoff. A detached hidden process owns claims and heartbeats; no interactive terminal is needed. It survives individual shell calls, but browser actions still require the host agent to keep working. A host cancellation or disconnected browser cannot be called a completed batch.

For new work, the Skill uses **Tabbit → built-in browser**. An explicit browser choice takes precedence; existing tasks resume in their original browser. No-login tasks run first. On a login wall it tries the selected browser's existing Google session once and verifies authentication. Unconfirmed login attempts close their task and provider tabs and rotate without a user question. Every materially progressed unfinished form is preserved for batch-end handoff.

## Installation failures

Version 1.9.1 and newer supports both Blink's server-managed release channel and the official Git repository at `https://github.com/era4d/blinklib-submit-skill`. Before each new controller starts, the selected source is checked and a changed release is installed atomically while three local versions are retained. API releases are SHA-256 verified. Git releases are cloned without an interactive credential prompt, resolved to an exact commit, checked for required files and unsafe symbolic links, and then activated.

Use `node scripts/blink-skill-manager.mjs check` to inspect the selected source, `update` to follow Blink's API default, `git-update` to switch to GitHub `main`, `git-update --ref v1.11.0` to install and pin a release tag, or `rollback` to restore and pin the newest retained local version. Once `git-update` succeeds, future automatic startup checks use GitHub until `update --source api` switches back. A server administrator can independently move the API default pointer to an older immutable release. Editing only the version in `connection.json` does not upgrade the executable.

An installation cloned directly from GitHub may also use ordinary `git pull --ff-only` while its tracked files are clean. `connection.json` and `.blink-release.json` are ignored and must never be committed. The bundled `git-update` command is preferred when atomic switching and local rollback history are desired.

If an agent reports that a script or reference is missing, reinstall the original Blink download as a complete package. Do not repair the installation by copying isolated files from another platform. If the API rejects the bundled credential, regenerate the download from Blink so it receives a fresh scoped connection.

## Automatic image uploads

Users do not need to configure upload directories, TEMP variables, or MCP workspace roots for the supported same-host Chrome DevTools connection. The installed Skill fetches project images through its bundled Blink connection, automatically stages them in the operating system temporary directory, calls the browser upload operation, and verifies the result. Windows, macOS, and Linux paths are selected by Node; no username or drive is hardcoded.

Use the selected browser's documented upload operation with matching API images. The default order for new work is **Tabbit → built-in browser**. Do not start Python Chrome merely to upload in Tabbit or the built-in browser. For an explicitly chosen or already active Python backend, the [Python runner](references/python-runner.md) retains a broker/MCP across commands and stdin EOF. Users do not configure a port, MCP entry or image paths. `session-status` checks it; `session-stop` disconnects only when requested. Remote browsers need their documented file-transfer capability; missing upload capabilities are reported while preserving the form.
